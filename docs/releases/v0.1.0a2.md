# Diagora v0.1.0a2 Release Notes (Milestone M1)

**Release Date:** 2026-11-24  
**Milestone:** M1 — Python & Node.js Diagnostics Engine  
**Status:** Public Alpha Pre-release

## Highlights

Diagora `v0.1.0a2` transitions the repository diagnostics CLI from the Phase 0 structural foundation to concrete, deterministic static diagnostics for Python and Node.js repositories.

### Python Diagnostics (`PY001`–`PY010`)

`PythonAnalyzer` inspects `pyproject.toml`, `requirements.txt`, `requirements-dev.txt`, `Pipfile`, `Pipfile.lock`, `poetry.lock`, `uv.lock`, `setup.cfg`, `setup.py` (via safe `ast.parse`, never executed), `.python-version`, and `runtime.txt`:

- Detects TOML/INI/Python syntax errors and invalid PEP 621 metadata (`PY002`).
- Validates PEP 440 Python version constraints and missing version declarations (`PY001`, `PY007`).
- Detects Python source roots without any dependency manifest (`PY003`).
- Flags missing lockfiles (`poetry.lock`, `uv.lock`, `Pipfile.lock`) only when the project configures a lockfile-oriented workflow (`PY004`).
- Detects intra-manifest and cross-manifest dependency version conflicts and invalid PEP 508 specs (`PY005`, `PY009`), missing/unsafe `-r`/`-c` includes, and lockfile-to-manifest drift (`PY009`).
- Detects missing `[build-system]` on distributable packages (`PY006`), missing dev/test dependency groups when tests exist (`PY008`), and nonexistent entry point modules (`PY010`).

### Node.js Diagnostics (`ND001`–`ND009`)

`NodeAnalyzer` inspects `package.json`, `package-lock.json`, `pnpm-lock.yaml`, `yarn.lock`, `pnpm-workspace.yaml`, `.npmrc`, `.nvmrc`, `.node-version`, and `tsconfig.json` (JSONC-aware):

- Detects malformed JSON and invalid `package.json` schemas (`ND001`).
- Checks Corepack `packageManager` declarations (`ND002`) and detects conflicting lockfiles within the same package directory or mismatches between `packageManager` and the committed lockfile (`ND003`).
- Checks `engines.node`, `.nvmrc`, `.node-version`, and `.npmrc` `engine-strict=true` consistency (`ND004`).
- Validates local relative script targets in `scripts` (`ND005`) and `main`/`module`/`types`/`bin` entry points (`ND006`).
- Validates `package.json` `workspaces`, `pnpm-workspace.yaml`, and `workspace:*` references (`ND007`).
- Validates `tsconfig.json` JSONC syntax and local `extends` references (`ND008`).
- Detects drift between `package.json` dependencies and committed `package-lock.json`, `pnpm-lock.yaml`, or `yarn.lock` (`ND009`).

### Rule Status & Honest Scan Reporting

- `diagora rules list` now displays whether each rule is `implemented` (`19` rules) or `deferred` (`20` rules) and supports `--status implemented|deferred|all`.
- `ScanSummary` records `analyzers_executed` and `execution_status` (`completed` vs. `no_applicable_analyzers`), ensuring repositories without applicable analyzers never display a false clean-scan pass.

### Security, Output & CI Hardening

- Extended secret redaction to scrub Google API keys (`AIza...`), npm/PyPI tokens, JWTs, and `Basic` auth headers across findings, warnings, and CLI error messages.
- Guarded JSON, TOML, YAML, and AST parsers against `RecursionError` on deeply nested inputs.
- Escaped untrusted repository strings in Rich terminal output (`rich.markup.escape`) and Markdown table cells.
- Added open-source governance and CI templates (`CODE_OF_CONDUCT.md`, `.github/ISSUE_TEMPLATE/`, `PULL_REQUEST_TEMPLATE.md`, `dependabot.yml`, SHA-pinned GitHub Actions with `pip-audit`).

- `ENV001`–`ENV006`, `DK001`–`DK010`, `DP001`–`DP003`: Environment, Docker, and Deployment static analyzers (M2).
