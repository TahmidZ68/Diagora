# Diagora v0.1.0a3 Release Notes (Milestone M2)

**Release Date:** 2026-11-26  
**Milestone:** M2 — Environment, Docker, Configuration & Deployment Diagnostics  
**Status:** Public Alpha Pre-release

## Highlights

Diagora `v0.1.0a3` completes Milestone M2 by adding concrete, deterministic static analyzers for Environment configuration, Docker & Compose, and Deployment / CI manifests—bringing the implemented rule catalog from `19` to **`38` implemented rules** (with `ND010` deferred to M3 opt-in runtime diagnostics).

### Environment & Secret Hygiene (`ENV001`–`ENV006`)

- Detects missing `.env.example` / `.env.sample` when Compose, deployment configs, or `.env` files actively reference variables (`ENV001`).
- Flags referenced variables absent from `.env.example` while ignoring OS/CI system variables (`ENV002`).
- Detects empty required declarations while preserving intentionally blank secret placeholders in `.env.example` (`ENV003`).
- Detects committed secrets/credentials across `.env*`, Compose, deployment, and CI configs via `detect_secret_pattern()` without exposing raw secret strings (`ENV004`).
- Flags duplicate/conflicting declarations in `.env*` files (`ENV005`) and stale unused example variables (`ENV006`).

### Docker & Compose (`DK001`–`DK010`)

- Validates Compose YAML structure (`DK003`), build context existence/containment (`DK002`), and Dockerfile paths (`DK001`).
- Verifies `env_file` targets (`DK004`), Dockerfile `EXPOSE` vs. Compose `ports` consistency (`DK005`), and `HEALTHCHECK` / `healthcheck` coverage (`DK006`).
- Detects undefined `depends_on`/`links`/`network_mode` service references (`DK007`), `privileged: true` or host namespace sharing (`DK008`), sensitive/escaped/missing bind mounts (`DK009`), and missing `.dockerignore` files (`DK010`).

### Deployment & CI (`DP001`–`DP003`)

- Validates YAML/JSON/TOML syntax and workflow structure across `.github/workflows/*.yml`, `vercel.json`, `render.yaml`, `fly.toml`, `railway.json`, and `netlify.toml` (`DP001`).
- Detects missing local script/Dockerfile/action targets referenced by CI workflows and deployment manifests (`DP002`).
- Checks configured Python/Node runtime versions against project constraints while avoiding false positives on multi-version CI test matrices (`DP003`).
